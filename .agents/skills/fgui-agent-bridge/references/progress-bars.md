# 百分比进度条制作与验收

先核对实际使用的组件、资源 ID 和运行时代码，不能仅对照一个 UI。换皮沿用固定主参考，再比较至少一个同族实现；保留已有业务和手工布局。

## FTS 客户端约定

- 百分比按真实目标计算，目标非正时按既有业务处理，不能猜目标或加业务兜底。显示值钳制到 0–100；整数显示沿用项目取整方式，进度条和百分比文字必须使用同一个计算结果，`max=100`。例如 3/10 显示 30%，0.5% 取整为 0 时条也为 0。计数 `3/10` 独立显示，不替换为百分比。
- 进度填充图片默认使用 package.xml 的 `scale="tile"`，按资源 ID 核对实际引用，不能只看 fileName。纹理重复、图案比例、圆角/遮罩和低进度端点均需检查，不能把平铺改成拉伸或九宫格来补视觉问题。美术有明确特殊要求时说明精确差异，不批量修改公共图片或旧皮肤。
- 已保存 XML 中的 ProgressBar 默认值、实例覆盖值和配对文字一致；例如 30% 对应 value=30/max=100。更改资源缩放前搜索全部引用，确认共享范围。

## 只读源检查

对本次制作/修改的百分比且要求平铺的组件运行（路径按当前工作区填写）：

```bash
python3 <SKILL_DIR>/scripts/check_progress_bars.py \
  --project <FGUI_PROJECT> \
  --component ju_spin_stash_task/com/task_item_default
```

可重复 `--component` 检查多个条目。检查递归 component 引用、有效 ProgressBar 默认/实例覆盖、0–100 范围、唯一配对的 `progress_text` 或内部 `title` 数字百分比，以及 bar/bar_v 下实际填充图片的平铺与文件存在性。非零退出须修正或记录具体不适用原因，不得静默跳过。人工确认原图自带不可重复端点、直接平铺出现接缝时，才可用 `--nine-grid-image <PACKAGE_ID/IMAGE_ID> "<素材原因>"` 记录精确九宫格例外；未命中资源、缺失文件或拉伸不会因此通过。脚本不连接、切换、保存或发布编辑器。

边界：仅检查已保存基础分支 XML；列表 item/defaultItem 请直接指定其条目组件，代码动态填充、Gear/Controller 覆盖、多条进度的自定义文字配对及图形/自定义填充需人工核对。计数文字不被当作百分比；图片文件存在不等于成功解码。此工具不能证明计算逻辑或纹理渲染正确，不适用于原始计数 max=目标值的进度条。

## 编辑器与游戏验收

有预览授权时，在隔离工程副本对比至少两个同族条目和一个其他布局的进度条。覆盖 0、低于 1%、30%、100%、超目标输入；超目标应由已有业务计算钳制为 100，不能直接把越界值留给 UI。核对同一显示值、纹理重复、端点、遮罩、默认文字和进度动画。保留用户当前文档及未保存修改，不为验证擅自发布。

分别报告源检查、编辑器原生预览、实际加载的游戏运行时结果；未运行游戏时明确未验证。小数显示、无效目标、完成后重置等边界按现有业务验收，不借通用规范改写领奖/活动逻辑。
