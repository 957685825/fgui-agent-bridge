# 换皮位置复用与差异验收

换皮开始时读取本文件。默认复用旧皮肤已成立的显示契约；不因新图看起来相近就重摆整页。

## 开工前固定参考

1. 用户指定参考时以它为主；否则查看同族至少两个已有皮肤，按实际运行路径选一个主参考，另一个只用于交叉核对。记录主参考、目标工程、涉及的组件和实际加载它们的业务代码。不能从不同皮肤随意拼凑布局。
2. 先读父组件及任务项、进度条、奖励组件、按钮，确认画布、pivot/anchor、缩放、裁切和滚动范围。核对运行时是否设置列表数据、动态加载奖励、改变宽高或覆盖位置；这些状态不能从静态预览推断。
3. 默认保留结构、对象 ID/名称、Controller/Transition、列表间距、文本排版和动态奖励挂点。新美术有尺寸差异时，按原图实际非透明边缘及设计图测量；每项调整说明具体理由。使用原始切图，不为补位置自行裁切、预旋转或补画。
4. 把设计图放在 designImage，不加入运行时显示列表。叠图时统一画布、原点、缩放及状态；复查文字与舞台边界时临时查看无设计图叠加的结果，区分参考图的残影与真实 UI。不擅改用户当前编辑器设置。

## 只读检查旧新布局差异

随 Skill 分发的脚本无需 MCP 或编辑器连接，读取已保存基础分支 XML，不修改工程或自动移动节点。在 Skill 所在目录运行：

```bash
python3 scripts/compare_skin_layout.py \
  --reference PATH/TO/OLD/FairyGUI.fairy \
  --target PATH/TO/NEW/FairyGUI.fairy \
  --component ju_example/PopupExample \
  --component ju_example/PopupInfo
```

- 两端必须使用相同的包/组件路径；以稳定对象 ID 配对，重命名、增删、层级及显示顺序变化都应复核，不靠位置或模糊名称猜配。脚本递归检查组件实例、列表默认项及滚动条引用，按 package/resource ID 解析，不能用 fileName 掩盖错误引用。
- 对比根尺寸、xy/size、pivot/anchor、scale、分组、列表间距/边距、文本排版属性，以及 Controller、Gear、Relation、Transition 的序列化属性。美术源图、文案和纯颜色替换不作为布局差异；字体度量、图片透明边缘仍须视觉检查。
- 任何未确认差异返回退出码 1；无差异或全部精确确认返回 0。差异是复查项，不自动等于错误。缺失引用、未导出跨包组件、重复局部 ID、循环引用等读取失败也返回 1，不能略过后报通过。
- 有意变化可以写入暂存区 JSON 数组，再传 `--review PATH/TO/review.json`。每项从报告 differences 复制完整的 component/node/property/before/after，增加非空 reason。必须精确匹配当前值，过期或重复记录会失败。不提供批量确认、通配忽略或自动接受所有差异的开关。

例如一项经测量确认的变动：

```json
[
  {"component":"ju_example/PopupExample","node":"reward_mount","property":"xy",
   "before":"760,240","after":"780,240","reason":"新奖励框可见中心向右 20 px，保持挂点与框中心一致"}
]
```

该检查仅覆盖已保存基础 XML；不读取未保存编辑器文档、分支覆盖或游戏动态数据，不计算状态切换后的最终屏幕位置，也不校验引用图片是否存在。使用分支时另行核对实际加载分支。跨皮肤包/组件路径不同时，先人工明确对应关系，不能伪造一份已改名的参考来消除差异。

## 分开验收三种结果

| 结果 | 必查内容 | 通过的证据 |
| --- | --- | --- |
| 源文件 | 主参考与目标差异；逐项修正或解释 | 只读报告、精确差异原因 |
| 编辑器默认状态 | 列表分组标题/间隔、首末项、奖励挂点、裁切、舞台边界 | 在获得操作授权后读取实际对象树及同状态预览；只有 XML 时标记待验 |
| 游戏动态状态 | 实际任务列表与分组、滚动到底、奖励加载后位置、进度 0/30/100、Controller 各相关页、长译文 | 实际运行截图/测量；缺少条件时明确待验，不能用合成预览代替 |

任务列表应同时核对行高、组间隔、右侧奖励框/挂点/数量文本与进度条。奖励图标沿用原有动态资源加载；不要放静态通用奖励图标掩盖挂点偏移。多语言按项目已支持语言检查完整句子及文本框边界，遵循用户明确排除项。

交付说明哪些检查已完成、哪些待验；源检查返回 ok 不代表视觉正确。保留用户手工布局，不顺带改业务、发布设置或公共组件。保存、编辑器操作、FGUI 发布和游戏构建分别遵循用户授权，不为完成检查自行触发。
